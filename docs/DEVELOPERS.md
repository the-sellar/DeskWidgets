# DeskWidgets для разработчиков

Как запустить из исходников, собрать .exe и как устроен код. Если вам нужно просто пользоваться программой, читайте [README](../README.md).

Стек: Python 3.12–3.13, PySide6 (Qt 6), pywinrt (медиа-сессии), psutil, pycaw, nvidia-ml-py, pythonnet (LibreHardwareMonitor), PyInstaller.

---

## Запуск из исходников

1. Установите Python **3.12 или 3.13** (64-bit) с https://www.python.org/downloads/windows/ с галочкой «Add python.exe to PATH». На 3.14 пока может не оказаться готовых пакетов pythonnet/winrt.
2. В папке проекта:
   ```powershell
   py -3.13 -m venv .venv
   .venv\Scripts\activate
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   python main.py
   ```
   Без окна консоли: `.venv\Scripts\pythonw.exe main.py`.

> Если PowerShell пишет «выполнение сценариев отключено», один раз выполните
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

## Сборка .exe

```powershell
.venv\Scripts\activate
python build.py
```

Результат — `dist\DeskWidgets.exe` (~50 МБ, один файл, Python не нужен). Если в `lib` лежат DLL LibreHardwareMonitor, они скопируются в `dist\lib`.

Другие скрипты в `tools`:

| Скрипт | Что делает |
|---|---|
| `make_icon.py` | рисует `assets\icon.ico` (его вызывает `build.py`) |
| `make_shortcuts.py` | ярлыки на `dist\DeskWidgets.exe` на рабочем столе и в «Пуске» |
| `make_screenshots.py` | картинки для README на выдуманных данных → `docs\screenshots` |

В Диспетчере задач у собранной программы два процесса в группе DeskWidgets: так работает однофайловая сборка PyInstaller (первый процесс распаковывает, второй работает).

```
├── requirements.txt

├── tools/                      иконка, ярлыки, скриншоты
├── docs/                       эта документация и скриншоты
└── deskwidgets/
    ├── app.py                  главный объект: модули, таймеры, расстановка виджетов по мониторам
    ├── config.py               настройки (JSON, значения по умолчанию, сигнал «изменилось»)
    ├── logger.py               лог ошибок
    ├── paths.py                пути к файлам, команда для автозапуска
    ├── tray.py                 иконка в трее и её меню
    ├── theme.py                темы, цвета, пресеты, иконка программы
    ├── theme_menu.py           меню «Тема»
    ├── volume.py               системная громкость (pycaw)
    ├── autostart.py            автозапуск (реестр) и запуск от админа (Планировщик заданий)
    ├── winutils.py             Windows API: «сквозные» клики, полноэкранные окна, UAC
    ├── widget_base.py          базовое окно-виджет: перетаскивание, масштаб, прилипание, прозрачность
    ├── ui_parts.py             подпись с «…», полоса прогресса, ползунок, кнопка-значок
    ├── settings_window.py      окно настроек
    └── modules/
        ├── base_module.py      базовый класс модуля + защита от ошибок
        ├── media_backend.py    фоновый поток: медиа-сессии Windows (WinRT)
        ├── now_playing.py      «Сейчас играет»
        ├── sensors.py          сеть, температура GPU (NVML) и CPU (LibreHardwareMonitor)
        ├── vpn.py              проверка VPN: процесс, адаптер, внешний IP
        ├── monitor.py          «Монитор»
        ├── shutdown.py         «Таймер выключения»
        ├── macros.py           «Макросы»: панель из 4 кнопок
        └── macro_engine.py     выполнение шагов макроса: запуск, поиск окна, перенос на монитор
```

Настройки — `%APPDATA%\DeskWidgets\config.json`, лог — `%APPDATA%\DeskWidgets\log.txt`. Испорченный файл настроек переименовывается в `config.json.bad`, и программа стартует с настройками по умолчанию.

## Как устроено

- **Модули.** Каждый модуль наследуется от `BaseModule` и лежит в своём файле. `app.py` импортирует модуль только если он включён, и всё оборачивает в `try/except`: упавший модуль не роняет остальные. Ошибки идут в лог (одинаковые — не чаще раза в 5 минут). Чтобы добавить модуль, достаточно записать его в `MODULES` в `app.py`. `build.py` забирает весь пакет целиком, так что ничего больше прописывать не нужно.
- **Настройки.** `Config.set("ключ.через.точку", значение)` через 0.5 с сохраняет файл и шлёт Qt-сигнал `changed`. Виджеты на него подписаны, поэтому всё применяется без перезапуска. При загрузке значения неправильного типа заменяются умолчаниями.
- **Потоки.** WinRT, датчики, список процессов, запрос IP и макросы работают в фоновых потоках и присылают результат сигналом Qt. Интерфейс обновляется раз в секунду.
- **Прозрачность при наведении.** Окну ставится `WS_EX_TRANSPARENT`, и клики уходят в окно под виджетом. Событий мыши виджет тогда не получает, поэтому курсор опрашивается таймером (~15 раз в секунду). Ctrl временно отключает эффект.
- **Мониторы.** Позиция хранится относительно монитора вместе с его «отпечатком» (производитель/модель/серийник). Если монитор отключили, виджет переезжает на основной, сохраняя привязку к ближайшему углу.
- **Полноэкранные окна** ищутся по Z-порядку окон (`winutils.fullscreen_monitors`). Прозрачные оверлеи вроде NVIDIA/Discord игнорируются.
- **Запуск от администратора** — задача Планировщика с `RunLevel=HighestAvailable`. Обычный запуск без прав просит Планировщик запустить задачу (без UAC) и сам закрывается.

## Температура CPU (LibreHardwareMonitor)

1. Скачайте архив с https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases (если есть выбор — с `net472` в названии).
2. Положите **все `.dll`** из архива в `lib` (рядом с `main.py` или `DeskWidgets.exe`) и снимите метку «из интернета»:
   ```powershell
   Get-ChildItem .\lib\*.dll | Unblock-File
   ```
3. Нужны права администратора: датчики процессора читаются через драйвер ядра. Альтернатива без прав — запущенное приложение LibreHardwareMonitor: оно публикует датчики в WMI, и программа читает их оттуда.

| Что написано на виджете | Что делать |
|---|---|
| «нужны права администратора» | Настройки → Общие → «Запускать от администратора», или запустите приложение LibreHardwareMonitor |
| «нет LibreHardwareMonitorLib.dll» | положите DLL в `lib` или укажите путь в Настройки → Монитор |
| «ошибка загрузки DLL» | почти всегда не снята блокировка (`Unblock-File`) или нет `HidSharp.dll` рядом |
| «нет данных (нужен драйвер)» | новые версии LHM используют драйвер PawnIO — запустите LibreHardwareMonitor от администратора, он предложит установить |
| «запустите LibreHardwareMonitor» | выбран источник WMI, а приложение не запущено |
